Risk-First Advisory

Local plug-and-play demo
What the AI does
Reads KYC, flags contradictions
Proposes a preliminary risk profile and surfaces tensions between scores, horizon and free-text answers. The AI never decides — it never approves a profile, never picks a portfolio, never signs anything.
What the advisor does
Approves, modifies or rejects
Reviews the AI proposal, lands the approved profile, signs off any risk-budget overrides and selects the final portfolio variant the client will see. The advisor is always the binding actor.
What stays auditable
Hash-chained, PII-redacted
Every meaningful step is appended to a SHA-256 chain per case. AI calls are stored with PII redacted by the backend. Compliance gets a single snapshot of summary + audit + AI logs in one click.

Section 1 · Case selector

1. Workbench case_id
Sections 2–4 · Profile
From client data to an approved risk profile
The AI proposes; the advisor decides. The approved profile is the input to everything downstream.
2. KYC Submission — POST /cases/{case_id}/kyc

Reasonable demo defaults. All fields editable. The backend validates ranges (age 18–120, scores 1–10, horizon > 0, etc.).

3. AI Profile Analysis — POST /cases/{case_id}/ai/profile-analysis

If kyc_submission_id is empty, the backend uses case.current_kyc_submission_id. Requires OPENAI_API_KEY in the backend env; without it, returns 400 — use the smoke check instead.

4. Advisor Profile Approval — POST /cases/{case_id}/profile-approval

proposed_profile is pre-filled from the latest analysis if one exists. approved_profile: empty on approve (backend auto-fills) and reject; required for modify.

Sections 5–6 · Portfolio inputs
Preferences + universe filter
Translate client preferences (manual JSON or NLP) into an eligible instrument universe.
5. Investment Preferences — POST /cases/{case_id}/investment-preferences

Manual mode with structured_preferences JSON. For NLP (AI extraction), clear the JSON and put text in the textarea; if both are present, structured wins and the text is kept as context.

6. Universe Filter — POST /cases/{case_id}/universe-filter

Applies the current preferences to the universe CSV via PreferenceFilterEngine. Empty preference_id → uses the case's current preference.

Sections 7–9 · Portfolio decisions
Proposal · override · final selection
Generate candidates, sign off any risk-budget override, and pick the final variant the client will see.
7. Portfolio Proposal — POST /cases/{case_id}/portfolio-proposal

Generates DEFENSIVE / BALANCED / GROWTH candidates from the current filter run + current approved profile.

8. Override Approval — POST /cases/{case_id}/override-approval

Approve / reject the override for a candidate that exceeds the approved risk budget (typically GROWTH). If the current proposal has a candidate that requires override, it's pre-selected.

9. Portfolio Selection — POST /cases/{case_id}/portfolio-selection

Advisor's final selection. If the variant requires override, supply an approved override_approval_id (current if empty). If the variant doesn't require override, leave it empty.

Sections 10–11 · Outputs
Client-facing report + final state
Generate the deterministic Markdown report and refresh the consolidated summary.
10. Report Generation — POST /cases/{case_id}/reports

Deterministic Markdown that consolidates the final selection. No PDF yet. Versioned per case (UNIQUE(case_id, version)).

11. Compact final summary

Refreshes the case summary and shows portfolio-side flags and derived IDs.

Sections 12–15 · Audit & Compliance
Hash-chain · verification · AI logs · snapshot
Verification + AI logs require dev-compliance-token (or any token with admin / compliance).
12. Audit Trail — GET /cases/{case_id}/audit

Chronological list of AuditEvent for the case (SHA-256 hash chain). Any valid role can read.

13. Audit Verification — GET /cases/{case_id}/audit/verify

Recomputes the hash chain and reports is_intact. Requires role admin or compliance — switch the Dashboard token to dev-compliance-token if needed.

14. AI Request Logs — GET /cases/{case_id}/ai-logs

Persisted OpenAI calls for this case. input_redacted is the version sanitized by the backend (free text + client_id redacted). Requires role admin or compliance.

Privacy: raw_response and non-whitelisted fields are stored unredacted at the API level. Review before sharing exports.
15. Compliance Snapshot

Combined view: summary + audit/verify + ai-logs in one render. Useful as a compliance review handoff. If the current token lacks admin / compliance, the verify / ai-logs sub-requests appear as "skipped (403)".

AI Filtered Portfolio Demo — POST /ai/filtered-portfolio-demo

OpenAI + universe + portfolio · no persist
Requiere OPENAI_API_KEY en la terminal donde corre uvicorn.
  • Paso 1 — la IA (OpenAI) extrae preferencias estructuradas desde texto libre del cliente.
  • Paso 2 — PreferenceFilterEngine filtra el universo CSV con esas preferencias.
  • Paso 3 — InstrumentMarketDataAdapter convierte los elegibles a snapshots de mercado.
  • Paso 4 — ReturnEstimator + CovarianceEngine + PortfolioGenerationCoordinator generan hasta 3 variantes (DEFENSIVE / BALANCED / GROWTH).
  • Si el universo filtrado es insuficiente o no es factible, devuelve el motivo del bloqueo sin generar portfolios.
  • No persiste resultados. No aprueba ningún perfil. Solo para demo.
