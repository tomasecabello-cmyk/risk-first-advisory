Risk-First Advisory

Demo local plug-and-play
Qué hace la IA
Propone — nunca decide
Lee el KYC estructurado y las respuestas en texto libre. Propone un perfil de riesgo preliminar y marca contradicciones. Nunca aprueba una cartera, nunca firma nada, nunca convierte una recomendación en final.
Qué hace el asesor
Firma cada paso
Revisa la propuesta de la IA, aprueba / modifica / rechaza el perfil, firma cualquier override del presupuesto de riesgo y selecciona la variante final. El asesor es siempre el actor vinculante.
Qué controla el sistema
Suitability y límites de riesgo
Governance, ESG, data quality y presupuesto de riesgo se verifican en cada paso. Las variantes que exceden el presupuesto aprobado quedan bloqueadas hasta que el asesor firme un override explícito.
Qué queda auditado
Cada decisión, encadenada con hash
Cada paso significativo se agrega a una cadena SHA-256 por caso. Las llamadas a la IA se guardan con la PII redactada por el backend. Compliance obtiene un snapshot único de resumen + auditoría + logs de IA en un click.
Recorrido recomendado
Nueve clicks, pensado para asesores
Si nunca viste la demo, seguí estos pasos en orden.
  1. 1 Hacé clic en el CTA del hero "Abrir case_demo_local en el Workbench" — pre-completa el caso demo y te lleva directo al flujo.
  2. 2 Mirá el resumen del caso que se carga solo (estado, porcentaje de avance, próxima acción sugerida).
  3. 3 Enviá el KYC (Paso 2) — los valores por defecto ya son razonables para un cliente de riesgo moderado; solo hacé clic en Enviar KYC.
  4. 4 Corré el análisis de IA del perfil (Paso 3). Requiere OPENAI_API_KEY; si no está configurada, saltá este paso y explicá que el smoke check del backend lo cubre con un mock determinístico.
  5. 5 Aprobá el perfil (Paso 4) — la primera decisión formal del asesor. Probá también la opción modify: muestra que el sistema registra el cambio.
  6. 6 Enviá las preferencias + corré el filtro de universo (Pasos 5–6) — traduce las preferencias del cliente en una lista de instrumentos elegibles.
  7. 7 Generá la propuesta de cartera (Paso 7) — aparecen las variantes DEFENSIVE / BALANCED / GROWTH; GROWTH típicamente requiere override.
  8. 8 Firmá el override + seleccioná la variante final + generá el reporte (Pasos 8–10) — las decisiones vinculantes del asesor, más el reporte Markdown revisable.
  9. 9 Cambiá el token del Dashboard a dev-compliance-token, después hacé clic en Verificar cadena de auditoría (Paso 13) — cierra la demo con foco en compliance.
▸ Guion de presentación Talk track de 90 segundos para un profesor de finanzas o un asesor no técnico
  1. "Esto es un backend de asesoría de inversiones." El KYC y las preferencias del cliente se transforman en una cartera aprobada por el asesor, con auditoría completa. Hacé clic en el CTA del hero para cargar el caso demo.
  2. "La IA nunca decide." Mostrá el Paso 3 (Análisis de perfil con IA). Propone un perfil de riesgo y detecta contradicciones en las respuestas del cliente. Nada es vinculante.
  3. "El asesor firma cada paso." Mostrá el Paso 4 (Aprobación del perfil): approve, modify o reject. El mismo patrón se repite en el override (Paso 8) y en la selección final de la cartera (Paso 9).
  4. "El sistema controla suitability y riesgo." Cuando GROWTH excede el presupuesto de riesgo aprobado (Paso 7), la variante queda marcada y no se puede seleccionar sin un override explícito del asesor (Paso 8). Suitability / ESG / data quality corren automáticamente.
  5. "El resultado es revisable, no es asesoramiento automático." El Paso 10 produce un reporte Markdown que el asesor revisa antes de que la firma se lo entregue al cliente. No hay un botón de "enviar al cliente con un click".
  6. "Cada decisión queda auditada." Cerrá en el Paso 12 (Audit Trail) + Paso 13 (Verificar cadena de auditoría): cadena hash SHA-256 por caso, chequeo de integridad en una sola llamada. El Paso 15 empaqueta resumen + auditoría + logs de IA en un snapshot único para compliance.

No es production-ready. Solo demo local de desarrollo — no es asesoramiento financiero, no se usa con PII real de clientes, no tiene auth productiva ni firm-level isolation.

Paso 1 · Abrir el caso

Usá case_demo_local creado por el seed del Dashboard, o cualquier case_id que ya tengas.
1. case_id del Workbench
Pasos 2–4 · Perfil del cliente & aprobación de riesgo
De las respuestas del cliente al perfil aprobado por el asesor
La IA propone un perfil preliminar; el asesor lo aprueba, lo modifica o lo rechaza. El perfil aprobado conduce todo lo de abajo.
2. Envío del KYC — POST /cases/{case_id}/kyc

Valores por defecto razonables para el demo. Todos los campos son editables. El backend valida rangos (edad 18–120, scores 1–10, horizonte > 0, etc.).

3. Análisis de perfil con IA — POST /cases/{case_id}/ai/profile-analysis

Si kyc_submission_id queda vacío, el backend usa case.current_kyc_submission_id. Requiere OPENAI_API_KEY en el entorno del backend; sin ella, devuelve 400 — usar el smoke check como alternativa.

4. Aprobación del perfil por el asesor — POST /cases/{case_id}/profile-approval

proposed_profile se prellena con el último análisis si existe. approved_profile: vacío en approve (el backend lo completa) y en reject; requerido en modify.

Pasos 5–6 · Universo de inversión
Capturar preferencias, filtrar instrumentos elegibles
Traduce las preferencias del cliente al universo de instrumentos sobre el que va a trabajar el optimizador.
5. Preferencias de inversión — POST /cases/{case_id}/investment-preferences

Modo manual con JSON en structured_preferences. Para extracción NLP (IA), borrá el JSON y poné texto en el textarea; si están ambos, gana el structured y el texto queda como contexto.

6. Filtro del universo — POST /cases/{case_id}/universe-filter

Aplica las preferencias vigentes al CSV del universo vía PreferenceFilterEngine. Si preference_id queda vacío → usa la preferencia actual del caso.

Pasos 7–9 · Decisiones del asesor
Propuesta, firma del override, selección final
Si una variante candidata excede el presupuesto de riesgo aprobado, el asesor debe firmar un override por escrito antes de poder seleccionarla.
7. Propuesta de cartera — POST /cases/{case_id}/portfolio-proposal

Genera las variantes DEFENSIVE / BALANCED / GROWTH a partir del filtro actual + el perfil aprobado actual.

8. Firma del override — POST /cases/{case_id}/override-approval

Aprobar / rechazar el override de una variante que excede el presupuesto de riesgo aprobado (típicamente GROWTH). Si la propuesta actual tiene una variante que requiere override, queda pre-seleccionada.

9. Selección de cartera — POST /cases/{case_id}/portfolio-selection

La selección final del asesor. Si la variante requiere override, pasá un override_approval_id aprobado (current si lo dejás vacío). Si la variante no requiere override, dejá el campo vacío.

Pasos 10–11 · Entregable al cliente
Un reporte revisable — no es una recomendación automática
El reporte es Markdown determinístico que el asesor revisa antes de compartir con el cliente. No hay botón de "enviar al cliente".
10. Generación del reporte — POST /cases/{case_id}/reports

Markdown determinístico que consolida la selección final. Sin PDF por ahora. Versionado por caso (UNIQUE(case_id, version)).

11. Resumen final compacto

Refresca el resumen del caso y muestra los flags del tramo de cartera + IDs derivados.

Pasos 12–15 · Evidencia para compliance
Audit trail, verificación de integridad, logs de IA, snapshot único
Cambiá el token del Dashboard a dev-compliance-token (o cualquier rol admin/compliance) antes de hacer clic en Verificar cadena de auditoría o Cargar logs de IA.
12. Audit Trail — GET /cases/{case_id}/audit

Lista cronológica de AuditEvent del caso (cadena hash SHA-256). Cualquier rol válido puede leer.

13. Verificación de auditoría — GET /cases/{case_id}/audit/verify

Recomputa la cadena hash y reporta is_intact. Requiere rol admin o compliance — cambiá el token del Dashboard a dev-compliance-token si hace falta.

14. Logs de llamadas a la IA — GET /cases/{case_id}/ai-logs

Llamadas a OpenAI persistidas para este caso. input_redacted es la versión sanitizada por el backend (texto libre + client_id redactados). Requiere rol admin o compliance.

Privacidad: raw_response y los campos fuera de la whitelist se guardan sin redactar a nivel API. Revisar antes de compartir exportes.
15. Snapshot de compliance

Vista combinada: summary + audit/verify + ai-logs en un solo render. Útil como handoff a compliance. Si el token actual no tiene admin / compliance, las sub-requests de verify / ai-logs aparecen como "skipped (403)".

Pendiente Fase 4: exportar el reporte como PDF, ZIP compliance-ready (reporte + auditoría + logs), market data provider en vivo, subida manual del universo, firm-level access control completo.   • Useful for validating the deterministic pipeline: governance → suitability → ESG → data quality → optimizer, plus SQLite persistence, audit trail and Markdown report.

AI Filtered Portfolio Demo — POST /ai/filtered-portfolio-demo

OpenAI + universe + portfolio · no persist
Requiere OPENAI_API_KEY en la terminal donde corre uvicorn.
