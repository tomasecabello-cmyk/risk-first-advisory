AI Filtered Portfolio Demo — POST /ai/filtered-portfolio-demo

OpenAI + universe + portfolio · no persist
Requiere OPENAI_API_KEY en la terminal donde corre uvicorn.
  • Paso 1 — la IA (OpenAI) extrae preferencias estructuradas desde texto libre del cliente.
  • Paso 2 — PreferenceFilterEngine filtra el universo CSV con esas preferencias.

Case Workbench — Phase 2 Workflow

case-scoped workflow · dev UI
Phase 2 case-scoped workflow — Workbench end-to-end.
  • Cubre el flujo completo: KYC → AI Profile Analysis → Profile Approval → Investment Preferences → Universe Filter → Portfolio Proposal → Override Approval → Portfolio Selection → Report.
  • El case_id debe existir previamente — crear vía Case Dashboard (sección 6 "Quick demo seed") o vía POST /cases directo.
  • Reusa el token del Case Dashboard (input cd-token); cambiar ahí afecta también acá.
  • Cada POST exitoso auto-refresca el summary. Los inputs downstream se autopopulan desde el último summary.
  • Audit panel completo y AI logs panel quedan pendientes (consultar vía GET /cases/{id}/audit / /admin/ai-logs en Swagger). PDF export pendiente (el report es markdown).
  • NOT production-ready. Sin firm-level access control, sin JWT, sin firma digital del advisor.
1. Workbench case_id
2. KYC Submission — POST /cases/{case_id}/kyc

Defaults demo razonables. Todos los campos editables. El backend valida rangos (age 18–120, scores 1–10, horizon > 0, etc.).

3. AI Profile Analysis — POST /cases/{case_id}/ai/profile-analysis

Si no se especifica kyc_submission_id, el backend usa case.current_kyc_submission_id. Requiere OPENAI_API_KEY en el entorno del backend; si no está configurada, devuelve 400.

4. Advisor Profile Approval — POST /cases/{case_id}/profile-approval

proposed_profile se prellena con el último análisis si existe. approved_profile: vacío en approve (backend auto-completa) y reject; requerido en modify.

5. Investment Preferences — POST /cases/{case_id}/investment-preferences

Modo manual con structured_preferences JSON. Si querés NLP (extracción IA), borrar el JSON y poner texto en el textarea opcional; si están ambos, structured manda y el texto queda como contexto (sin llamar IA).

6. Universe Filter — POST /cases/{case_id}/universe-filter

Aplica las preferences vigentes al universo CSV via PreferenceFilterEngine. Si preference_id vacío → usa la current del case.

7. Portfolio Proposal — POST /cases/{case_id}/portfolio-proposal

Genera DEFENSIVE / BALANCED / GROWTH a partir del filter run + approved profile current. Si variant_policy=standard (default), corre el coordinator estándar.

8. Override Approval — POST /cases/{case_id}/override-approval

Aprobar/rechazar override para una variante que excede el RiskBudget aprobado (típicamente GROWTH). Si el current proposal tiene candidate que requiere override, se preselecciona esa variante.

9. Portfolio Selection — POST /cases/{case_id}/portfolio-selection

Selección final del advisor. Si el variant requiere override, debe ir override_approval_id aprobado (current si vacío). Si el variant NO requiere override, dejar override_approval_id vacío.

10. Report Generation — POST /cases/{case_id}/reports

Markdown determinístico que consolida la selection final. Sin PDF todavía. Versionado por case (UNIQUE(case_id, version)).

11. Compact final summary

Refresca el summary del case y muestra los flags del segundo tramo del workflow + IDs derivados.

12. Audit Trail — GET /cases/{case_id}/audit

Lista cronológica de AuditEvent del case (hash chain SHA-256). Cualquier rol válido puede leer.

13. Audit Verification — GET /cases/{case_id}/audit/verify

Recomputa el hash chain y reporta is_intact. Requiere rol admin o compliance (advisor recibe 403). Cambiar token en Case Dashboard si es necesario.

14. AI Request Logs — GET /cases/{case_id}/ai-logs

Llamadas a OpenAI persistidas para este case. input_redacted es la versión sanitizada por backend (texto libre + client_id redactados). Requiere rol admin o compliance (advisor recibe 403).

Privacidad: los detalles "raw_response" y campos no whitelisted vienen sin redacción a nivel API. Revisar antes de compartir exportes.
15. Compliance Snapshot

Vista combinada: summary + audit/verify + ai-logs en un solo render. Útil para handoff a compliance review. Si el token actual no tiene rol admin/compliance, las partes verify/ai-logs aparecerán como "skipped (403)".

Pendiente Fase 3: PDF export del report, export package compliance-ready (ZIP con report + audit + logs), frontend cleanup / split, refresh automático de audit/logs después de cada POST (hoy es manual para evitar polling agresivo).
